# PostgreSQL по приватному IP без TLS

**Дата:** 2026-08-22
**Статус:** утверждено пользователем
**Область:** конфигурация подключения к PostgreSQL и безопасный релиз ветки `refactor`

## Цель

Разрешить приложению подключаться к Timeweb Managed PostgreSQL по приватному IPv4 без TLS, не ослабляя строгую TLS-проверку для доменных имён и публичных IP-адресов. После проверки изменение должно быть слито в `main` и отправлено на GitHub без запуска production-деплоя.

## Поведение подключения

TLS отключается только для:

- loopback-адресов `localhost`, `127.0.0.1` и `::1`;
- RFC1918 IPv4 `10.0.0.0/8`;
- RFC1918 IPv4 `172.16.0.0/12`;
- RFC1918 IPv4 `192.168.0.0/16`.

Для доменных имён, публичных IPv4 и остальных адресов приложение продолжает включать TLS с `rejectUnauthorized: true` и встроенным CA Timeweb. Новая env-переменная не добавляется: production-контракт остаётся равен семи значениям.

## Реализация

В `src/database-config.ts` появляется небольшая проверка приватного IPv4. `readDatabaseConfig` использует её вместе с существующей loopback-проверкой, чтобы определить значение `ssl`. Формат `DATABASE_URL`, создание пула и миграции не меняются.

## Тестирование

TDD-проверки должны сначала подтвердить текущее неверное поведение для приватных адресов, затем зафиксировать:

- отключение TLS для каждого RFC1918-диапазона;
- корректные границы диапазона `172.16.0.0/12`;
- сохранение TLS для публичного IPv4 и домена;
- отсутствие чтения CA, когда TLS отключён.

После реализации выполняются полный `npm test`, `npm run typecheck`, `npm run build`, `git diff --check` и сборка production Docker-образа.

## Интеграция и запрет production-деплоя

Перед push `main` нужно подтвердить, что App Platform не выполняет автодеплой из `main`. Если автодеплой включён или состояние нельзя надёжно определить, push `main` блокируется до отключения автодеплоя. Настройки Timeweb и production-деплой не изменяются без отдельного подтверждения пользователя.

После подтверждения ветка `refactor` сливается в локальную `main`, релизные проверки повторяются на результате merge, затем `main` отправляется в `origin` обычным fast-forward push без force push.

## Вне области

- включение публичного доступа к PostgreSQL;
- изменение семи production env-переменных;
- запуск миграций или seed в Managed PostgreSQL;
- деплой новой версии в App Platform;
- удаление локальных файлов с секретами.
