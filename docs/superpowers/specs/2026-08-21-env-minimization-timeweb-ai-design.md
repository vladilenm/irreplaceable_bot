# Минимизация env и переход на Timeweb AI Gateway

**Дата:** 2026-08-21
**Статус:** утверждено пользователем
**Область:** production-конфигурация бота, App Platform, Managed PostgreSQL, LLM и embeddings

## Цель

Сократить production-конфигурацию с 28 env-переменных до семи понятных значений. В панели Timeweb должны остаться только секреты и идентификаторы конкретного Telegram-окружения. Расписания, модели, лимиты и технические параметры становятся типизированными настройками проекта с тестируемыми дефолтами.

Проект разворачивается в одном клубном Telegram-чате и уже запущен в Timeweb App Platform. Новый сервер приложения не создаётся. Для хранения данных будет добавлен Timeweb Managed PostgreSQL, а доступ к LLM и embeddings будет идти через Timeweb AI Gateway.

## Целевой production-env

В App Platform остаются ровно семь переменных:

```env
BOT_TOKEN=
TARGET_CHAT_ID=
AI_RADAR_THREAD_ID=
THREAD_SUMMARY_THREAD_ID=
TRACKED_THREAD_IDS=
TIMEWEB_AI_TOKEN=
DATABASE_URL=
```

### Секреты

- `BOT_TOKEN` — токен Telegram-бота.
- `TIMEWEB_AI_TOKEN` — единый ключ Timeweb AI Gateway.
- `DATABASE_URL` — строка подключения, содержащая пароль пользователя PostgreSQL.

Значения секретов никогда не попадают в git, тестовые снапшоты или логи. `.env.example` содержит только пустые или локальные безопасные примеры.

### Идентификаторы окружения

- `TARGET_CHAT_ID` — единственный Telegram-чат, сообщения которого разрешено обрабатывать.
- `AI_RADAR_THREAD_ID` — тема для AI-дайджеста.
- `THREAD_SUMMARY_THREAD_ID` — тема для публикации ежедневных сводок.
- `TRACKED_THREAD_IDS` — CSV тем, входящих в ежедневные сводки.

Эти значения не являются секретами, но остаются в env как предохранитель от запуска production-бота не в том чате. Переносить их в репозиторий или объединять в JSON-переменную не требуется.

## Переменные, удаляемые из env

### AI

- `AI_API_KEY` заменяется на `TIMEWEB_AI_TOKEN`.
- `EMBEDDING_API_KEY` удаляется: LLM и embeddings используют один Gateway token.
- `AI_BASE_URL` удаляется: `https://api.timeweb.ai/v1` становится константой.
- `AI_MODEL` удаляется: chat-модель фиксируется в типизированной конфигурации после проверки фактического model ID через Gateway `/models`.
- `EMBEDDING_MODEL` удаляется: используется `openai/text-embedding-3-large`.

LLM и embedding-клиенты используют OpenAI SDK и один base URL. Наличие Anthropic SDK или совместимого кода само по себе не создаёт отдельную production-настройку.

### Расписания и retention

- `DIGEST_CRON` → `0 6 * * *` UTC, то есть 09:00 МСК.
- `THREAD_SUMMARY_CRON` → `30 3 * * *` UTC, то есть 06:30 МСК.
- `RETENTION_SWEEP_CRON` → `0 1 * * *` UTC, то есть 04:00 МСК.
- `MEMBER_INDEX_CRON` → `*/15 * * * *`.
- `MESSAGE_RETENTION_DAYS` → 90 дней.

Изменение расписания или retention выполняется обычным коммитом и деплоем. Эти параметры не должны незаметно расходиться между панелью и кодом.

### PostgreSQL

- `DATABASE_MIGRATION_URL` удаляется: миграции и runtime используют `DATABASE_URL`.
- `DATABASE_SSL` удаляется: TLS определяется по хосту URL.
- `DATABASE_CA_CERT` удаляется: публичный корневой сертификат Timeweb включается в Docker-образ как файл, а не как многострочный env.
- `DATABASE_POOL_MAX` → 5.
- `DATABASE_STATEMENT_TIMEOUT_MS` → 10 000 мс.

Для `localhost` и `127.0.0.1` TLS автоматически отключается, чтобы локальный Docker PostgreSQL не требовал сертификат. Для остальных хостов TLS обязателен с `rejectUnauthorized: true`. Production `DATABASE_URL` должен использовать доменное имя Timeweb, соответствующее сертификату, а не IP-адрес.

На минимальном Managed PostgreSQL допустим один пользователь для runtime и миграций. Когда проект потребует отдельной migration-роли, это оформляется как архитектурное изменение, а не как заранее пустующая переменная.

### Очередь, флаги и runtime

- `REQUEST_MATCHING_ENABLED` удаляется: готовая функция включена в production-конфигурации проекта.
- `REQUEST_MATCH_CONCURRENCY` → 2.
- `REQUEST_QUEUE_LIMIT` → 50.
- `REQUEST_PROCESSING_TIMEOUT_MINUTES` → 10 минут.
- `LOG_LEVEL` → `info`.
- `NODE_ENV` задаётся Docker-образом как `production`, а не в панели.
- `ALLOW_MOCK_MEMBER_SEED` удаляется. Production-seed двадцати тестовых карточек требует явного CLI-параметра, например `npm run seed:members -- --allow-production`; постоянный env-флаг не используется.

## Типизированная конфигурация

Технические значения размещаются в одном модуле конфигурации и экспортируются как неизменяемый объект. Код не должен читать удалённые env-переменные напрямую или поддерживать скрытые legacy-fallbacks.

Конфигурация содержит:

- Gateway base URL;
- chat model ID;
- embedding model и размерность;
- cron-расписания;
- retention;
- параметры пула PostgreSQL;
- лимиты очереди запросов;
- признак включённого member matching.

Парсер env отвечает только за семь перечисленных переменных и выдаёт понятную ошибку запуска для каждого отсутствующего или некорректного значения.

## Размерность embeddings

Текущая PostgreSQL-схема использует `vector(1536)`. Модель `openai/text-embedding-3-large` по умолчанию может возвращать вектор другой длины, поэтому до production-деплоя обязателен реальный probe через Timeweb AI Gateway:

1. создать Gateway token;
2. запросить список моделей и зафиксировать точный chat model ID;
3. вызвать embeddings с параметром `dimensions: 1536`;
4. проверить, что возвращено ровно 1536 конечных чисел;
5. только после успешной проверки создавать и заполнять production-индекс.

Если Gateway не поддерживает сокращение размерности, код не подстраивается молча. До деплоя создаётся отдельная миграция PostgreSQL на фактическую размерность, меняется константа и обновляются тесты. Размерность не становится env-переменной.

## Ошибки и наблюдаемость

- В логах допустимы имя провайдера, model ID, длительность и код ответа.
- Ключи, connection strings, тексты карточек и пользовательские запросы не логируются.
- При несовпадении размерности индекса и ответа embeddings запуск индексации завершается явной ошибкой.
- Если PostgreSQL или Gateway недоступны, приложение не имитирует успешный member matching.
- Telegram polling запускается только после миграций и проверки PostgreSQL, как предусмотрено существующей архитектурой.

## Изменения в репозитории

Реализация должна:

1. свести `.env.example` и `docker-compose.yml` к семи production-переменным;
2. добавить типизированные технические дефолты;
3. заменить два AI-ключа единым `TIMEWEB_AI_TOKEN`;
4. передать Gateway base URL и `dimensions` в embedding-клиент;
5. использовать один `DATABASE_URL` для runtime и миграций;
6. включить публичный CA Timeweb в Docker-образ и автоматически выбирать TLS для local/remote URL;
7. заменить production seed-флаг явным CLI-параметром;
8. обновить unit-, startup- и configuration-тесты;
9. обновить README и operations runbook;
10. удалить документацию про все 21 устаревшую env-переменную.

## Развёртывание

Порядок безопасного перехода:

1. локально реализовать и полностью проверить новый конфигурационный слой;
2. в Timeweb создать AI Gateway token и выполнить model/embedding probe;
3. создать минимальный Managed PostgreSQL с pgvector;
4. получить TLS connection string и проверить миграции;
5. заменить настройки существующего App Platform на семь переменных;
6. развернуть один экземпляр бота;
7. проверить startup, Telegram `/status` и отсутствие второго polling-инстанса;
8. однократно загрузить 20 mock-карточек явной seed-командой;
9. проверить несколько запросов `#запрос` и выдачу 3–5 участников.

Создание платных ресурсов и API-ключей в браузере требует отдельного подтверждения непосредственно перед финальным действием. До подтверждения разрешены просмотр конфигурации и подготовка формы.

## Рассмотренные альтернативы

### Четыре env-переменные

Telegram chat/thread IDs можно было бы хранить в git. Вариант отклонён: он повышает риск ошибочного запуска в другом чате и смешивает deployment identity с кодом.

### Один JSON env для Telegram

Объединение ID в `TELEGRAM_CONFIG` уменьшило бы число строк, но ухудшило редактирование, валидацию и диагностику ошибок в панели. Вариант отклонён.

### Сохранить все optional overrides

Вариант отклонён, потому что сохраняет две конкурирующие конфигурации — дефолты в коде и произвольные значения в панели — и со временем снова приводит к путанице.

## Критерии готовности

- `.env.example` содержит семь переменных и ни одной legacy-переменной.
- Приложение стартует локально с семью переменными и локальной PostgreSQL без TLS.
- Production-конфигурация требует TLS с проверкой сертификата.
- Один token используется для chat completions и embeddings.
- Все тесты, typecheck и production build проходят.
- Поиск по репозиторию не находит чтения 21 удалённой env-переменной вне исторических design/plan документов.
- Реальный Gateway probe подтверждает model ID и размерность до production-деплоя.
